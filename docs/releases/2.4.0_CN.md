# Code Space 发布说明 - 2.4.0

## 概览

Code Space 2.4.0 提升了大规模代码集合的浏览效率和管理安全性，同时修正代码嵌入范围并让编辑器显示更平滑。Dashboard 现在使用缓存文件索引和有界虚拟渲染；代码嵌入在交互式预览、Markdown 展开和 PDF 导出中使用一致的行范围处理。本版本还新增仓库自有的 Star History 自动化和带 provenance 证明的发布流程。

## 改进

### 提升大规模 Dashboard 浏览效率

Dashboard 现在可以更流畅地处理大量受管代码文件。

- 搜索、筛选和排序复用缓存文件索引，不再为每次交互重新扫描 Vault。
- 只渲染可见卡片和少量缓冲区域，在保持连续滚动的同时限制 DOM 工作量。
- 文件创建、删除、重命名和修改事件会增量更新索引。
- 保留现有卡片的颜色、字体、间距、边框和交互行为。

### 更安全的文件与视图生命周期

Code Space 现在会在创建或移除文件系统链接前更严格地校验外部挂载路径和链接归属。编辑器保存会检测外部冲突，搜索可以安全处理零长度正则表达式，嵌入、PDF、观察器和 popout 窗口的清理路径也会更可靠地释放资源。这些保护措施不改变既有工作流，同时降低数据丢失和视图过期风险。

### 更平滑的编辑器与嵌入显示

代码编辑器和代码嵌入的滚动条默认隐藏，滚动时淡入，编辑器获得焦点时保持显示。滚动能力和可用滚动区域保持不变。

## 问题修复

### 修正代码嵌入的闭区间范围

类似 `![[piper_leader.py#2-12]]` 的显式范围现在只显示第 2 到第 12 行。文件末尾换行和 Windows CRLF 换行不再造成额外的可见源码行；交互式嵌入、原生 Markdown 展开和 PDF 导出现在共用同一套规范化截取逻辑。

## 发布与维护自动化

### 仓库自有 Star History

README 图表现在使用由 GitHub Actions 生成的稳定仓库 PNG，不再依赖受限的托管 Star History 接口。工作流每天自动刷新，也支持手动运行。

### 带证明的发布资产

推送 SemVer 标签后，工作流会运行 lint、测试和生产构建，校验标签与 `manifest.json` 一致，生成 GitHub artifact attestation，并将 `main.js`、`manifest.json` 和 `styles.css` 发布为 Release 资产。

## 重要说明

- 最低支持的 Obsidian 版本仍为 `1.7.2`。
- 不需要迁移设置。
- 没有移除命令、文件关联或 Dashboard 操作。
- 发布资产为 `main.js`、`manifest.json` 和 `styles.css`。
