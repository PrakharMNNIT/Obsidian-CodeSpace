# Code Space Release Notes - 2.4.0

## Overview

Code Space 2.4.0 makes large code collections faster to browse and safer to manage, while correcting range embeds and smoothing editor presentation. The Dashboard now uses a cached file index and bounded virtual rendering, and code embeds use consistent line-range handling across interactive previews, Markdown expansion, and PDF export. This release also adds repository-owned Star History automation and provenance-attested release publishing.

## Improvements

### Faster Dashboard browsing at scale

The Dashboard now keeps large managed-file collections responsive.

- Search, filtering, and sorting reuse a cached file index instead of rescanning the Vault for every interaction.
- Only visible cards and a small overscan window are rendered, keeping DOM work bounded while preserving continuous scrolling.
- File create, delete, rename, and modify events update the index incrementally.
- Existing card colors, typography, spacing, borders, and interactions remain unchanged.

### Safer file and view lifecycle handling

Code Space now validates external mount paths and link ownership more carefully before creating or removing filesystem links. Editor saves detect external conflicts, search handles zero-length regular expressions safely, and embed, PDF, observer, and popout-window cleanup paths release their resources more reliably. These safeguards preserve existing workflows while reducing data-loss and stale-view risks.

### Smoother editor and embed presentation

Code editor and code embed scrollbars are hidden by default, fade in while scrolling, and remain visible while the editor is focused. The scrolling behavior and available scroll area are unchanged.

## Bug fixes

### Correct inclusive code embed ranges

Explicit ranges such as `![[piper_leader.py#2-12]]` now display exactly lines 2 through 12. Terminal newlines and Windows CRLF endings no longer create an extra visible source line, and the same normalized slicing behavior is used by interactive embeds, native Markdown expansion, and PDF export.

## Release and maintenance automation

### Repository-owned Star History

The README chart now uses a stable repository-owned PNG generated by GitHub Actions instead of the restricted hosted Star History endpoint. The workflow refreshes the chart daily and can also be started manually.

### Attested release assets

Pushing a SemVer tag now runs lint, tests, and the production build, verifies that the tag matches `manifest.json`, creates GitHub artifact attestations, and publishes `main.js`, `manifest.json`, and `styles.css` as the release assets.

## Important notes

- Minimum supported Obsidian version remains `1.7.2`.
- No settings migration is required.
- No commands, file associations, or Dashboard actions were removed.
- Release assets are `main.js`, `manifest.json`, and `styles.css`.
