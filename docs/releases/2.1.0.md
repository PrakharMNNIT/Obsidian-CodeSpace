# Code Space Release Notes - 2.1.0

## Overview

Code Space 2.1.0 focuses on editing polish and better workspace integration. Code embeds can now be opened into the workspace target you need, editor highlights follow Obsidian's theme and accent system more closely, and readability issues around custom code fonts and dark-theme comments have been addressed.

This release does not introduce breaking changes or require any settings migration.

## New features

### Flexible open targets for code embeds

Embedded code files are no longer limited to opening in the current pane.

- Click an embed header to open the source file in the current workspace leaf.
- Use `Ctrl/Cmd+Click` to open the source file in a new tab.
- Use `Ctrl/Cmd+Shift+Click` to open the source file in a new window.
- Use `Ctrl/Cmd+Alt+Click` to open the source file in a split view.
- Embed tooltips were updated in English and Chinese so the available shortcuts are visible at the point of use.

## Improvements

### Theme-aligned editor highlights

Editor selection and search highlighting now use Obsidian theme variables instead of fixed colors.

- Primary selections and active-line selections use accent-aware foreground and background values.
- Search matches and the current match use theme-aligned background, outline, and shadow styles.
- Same-word highlighting remains visible without overpowering the rest of the editor.

The result is a more consistent editor appearance across light themes, dark themes, and custom Obsidian themes.

### Code font and dark-theme readability

- Code Space now applies Obsidian's configured monospace font at the CodeMirror scroller layer used by both the main editor and embedded code views.
- Dark-mode comment colors were adjusted for better contrast in the editor, embedded previews, and related CSS fallback styles.

## Documentation

- Project screenshots were moved into `docs/img/`, and the English and Chinese README files were updated to use the new paths.
- Historical release notes for `1.1.0` through `2.0.0` were added under `docs/releases/` for easier maintenance.

## Important notes

- No commands, settings, or data formats were removed in this release.
- Release assets remain `main.js`, `manifest.json`, and `styles.css`.
